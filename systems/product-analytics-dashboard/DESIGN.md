# 新品推广数据工作台设计系统

状态：第二轮前端设计工艺与经营总览指标联动已实现并锁定视觉基线
日期：2026-07-24
视觉依据：`设计参考/IMG_8540.JPG` 至 `设计参考/IMG_8545.JPG`

## 1. 设计命题

这是一个供单品牌小团队每周持续使用的新品经营工作台。它的首要任务是让人从最新波段结果迅速进入品类与 SKU 证据，并在同一上下文内完成判断、评论和行动。

视觉气质定义为：**温暖、克制、有编辑感的精密工作台**。

界面应像一张被长期维护的商品经营工作桌：信息密度高，但每个层级都有呼吸；商品图片、数据、梯队和评论共同出现时仍保持清晰。它不是营销落地页，也不是通用后台模板。

## 2. 参考图共同语言

- 暖灰外壳与白色内容面形成轻微层级，而非纯白满屏。
- 左侧导航稳定、窄而清晰；内容区使用严格栅格。
- 大量使用 1px 细边框、低对比背景和非常轻的阴影。
- 圆角存在但克制，控件、卡片和大面板有明确层级。
- 黑色与灰色承担绝大多数信息，橙色与蓝色只用于重点和比较。
- 表格、图表与上下文侧栏并存，仍保留充分留白。
- 评论和详情使用右侧上下文栏，不让用户离开当前分析对象。

## 3. 视觉 Token

### 3.1 色彩

| Token | Hex | 用途 |
| --- | --- | --- |
| Canvas / 纸灰 | `#EEEDE9` | 应用外壳、页面间隙、导航底色 |
| Surface / 暖白 | `#F8F7F4` | 主内容背景、分组面板 |
| Panel / 白 | `#FFFFFF` | 卡片、表格、浮层 |
| Ink / 墨黑 | `#181A18` | 主文字、主操作、当前数据 |
| Muted / 铅灰 | `#747770` | 次文字、坐标轴、未选中状态 |
| Signal / 橙蓝 | `#F07B2D` / `#3B86D1` | 当前波段与对比波段；不用于装饰铺色 |

补充语义色仅用于明确状态：成功 `#2F9B68`、风险 `#D65A52`、提醒 `#C58A29`。语义色必须同时配文字或图标。

### 3.2 字体

- 中文正文与控件：`Noto Sans SC Variable`，400 / 500 / 600。
- 英文、数字与标题：`Geist Variable`，500 / 600。
- 表格数字、货号与指标值：`IBM Plex Mono`，400 / 500，并启用 tabular numbers。
- 字号体系：12 / 13 / 14 / 16 / 20 / 28 / 36px。
- 正文默认 14px、行高 22px；表格 13px；指标 28–36px。
- 大标题保持紧凑，不使用营销页面式超大字号。

### 3.3 间距与尺寸

- 基础单位：4px。
- 常用间距：8 / 12 / 16 / 20 / 24 / 32px。
- 图标轨道：64px；一级导航：224px；顶部栏：64px。
- 主内容左右留白：桌面 24px，宽屏 32px。
- 右侧上下文栏：360px；小于 1500px 时以覆盖抽屉出现。
- 表格行高：紧凑 44px、带商品图 56px。
- 控件高度：36px；主操作 40px。

### 3.4 圆角、边框与阴影

- 控件圆角：9px。
- 小卡片圆角：12px。
- 主要面板圆角：16px。
- 胶囊只用于筛选标签、状态和波段选择，不把普通按钮全部做成胶囊。
- 默认边框：`1px solid #E1DFDA`。
- 默认阴影：`0 1px 2px rgba(24, 26, 24, 0.04)`。
- 浮层阴影：`0 16px 40px rgba(24, 26, 24, 0.12)`。

## 4. 布局系统

应用使用稳定双层导航与可选上下文栏：

```text
┌──────┬────────────────┬──────────────────────────────────────┬──────────────┐
│ 图标 │ 一级导航       │ 顶部栏 / 波段织带                    │ 上下文栏     │
│ 轨道 │                ├──────────────────────────────────────┤ 评论 / 证据  │
│      │ 总览           │ 页面标题 + 全局筛选                  │ 负责人 / 动作│
│      │ 波段与周度     ├──────────────────────────────────────┤              │
│      │ SKU 工作台     │ 12 列主内容栅格                      │ 可收起       │
│      │ 品类梯队       │                                      │              │
│      │ 分析与行动     │                                      │              │
└──────┴────────────────┴──────────────────────────────────────┴──────────────┘
```

- 1180px 以上显示完整双层导航；768–1179px 只保留图标轨道，桌面也可用偏好或 `Ctrl/Cmd+B` 主动折叠文字导航。
- 1500px 以上常驻 360px 右侧上下文栏；1180–1499px 使用不改变主画布滚动位置的覆盖栏；小于 768px 时导航和上下文为互斥全高覆盖层。
- 主要数据区采用 12 列栅格，16px gutter；宽屏 20px gutter。
- 信息顺序固定为：状态与口径 → 变化 → 驱动 → 证据 → 行动。
- 页面首屏必须在没有交互时回答核心业务问题。

## 5. 标志性元素：波段织带

工作台唯一的强调性设计是页头的“波段织带”：一条连续、窄幅的波段时间轨道，像服装开发中的色卡边与织唛。

- 每个节点代表一个上新波段，显示波段名、日期和数据完整状态。
- 当前波段使用墨黑底与 2px 橙色下沿；对比波段使用蓝色细线。
- 节点宽度与时间顺序表达真实信息，不作为纯装饰。
- 点击节点切换全局波段；拖动或键盘方向键可浏览历史节点。
- 该元素只在总览、波段、SKU 和梯队页头出现一次，不在卡片内部重复。

## 6. 代表页面结构

### 6.1 总览

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 波段织带  7A ─ 7B ─ [7C]        截止 7月16日 · 完整度 96%          │
├─────────────────────────────────────────────────────────────────────┤
│ 7C 新品表现                     [与 7B 对比] [打开评论]              │
│ 销售额主指标 + 关键结论一句话                                      │
├─────────────┬─────────────┬─────────────┬─────────────┬─────────────┤
│ 访客        │ 买家        │ 支付转化率  │ 付费消耗    │ 整体 ROI    │
├─────────────────────────────────────────────────────────────────────┤
│ 当前分析 + 中性阅读问题   [1 主分析] [2 结果对照] [3 结构分解] [复位]│
├───────────────────────────┬─────────────────────────────────────────┤
│ 支付趋势 / 投放与效率     │ 流量与成交 / 品类结构                   │
├───────────────────────────┼─────────────────────────────────────────┤
│ SKU 集中度与异常          │ 需要跟进的动作                          │
└───────────────────────────┴─────────────────────────────────────────┘
```

总览主指标不是孤立大数字，而是“结果 + 对比 + 中性阅读问题”的组合。五张关键指标卡固定为商品访客数、支付买家数、支付转化率、付费消耗和整体 ROI，不强制四等分。

#### 6.1.1 指标透镜与证据焦点

- 总览同时维护“指标透镜”和“证据焦点”。指标透镜驱动整页卡片、图表角色、序列强调和品类口径；证据焦点只驱动右侧栏中的指标汇总、日级点或品类对象。
- 默认使用“支付结果”透镜：支付趋势为主分析、品类图为支付金额结构，五张关键指标卡均不伪装为选中。
- 访客、买家和支付转化率映射到“流量与成交”；付费消耗和整体 ROI 映射到“投放与效率”；支付趋势始终承担结果对照，品类始终承担结构分解。
- 四个图表固定为支付、效率、流量和品类，不因指标选择隐藏、重排或自动滚动。联动提示按当前指标生成带目标图名的编号证据路径：主分析回答指标自身变化，结果或驱动对照连接结果关系，结构分解进入品类；只在用户触发时定位。
- 指标卡“证据”在当前工作台内选中对应指标并直接打开右栏证据标签，不把用户带到原始 API 响应。原始证据链接只留在明确的证据界面中。
- 关闭右侧栏只关闭证据面板，不清除指标透镜；重复选择当前指标重新打开该指标汇总；“回到支付结果”是唯一显式复位动作。
- 指标值、日级转化率、比较值、不可计算原因和品类排序全部来自后端事实。前端只表达角色和强调，不重新计算经营指标，不生成自动经营结论或处置建议。

### 6.2 SKU 工作台

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 7C · SKU 工作台       搜索货号     品类 / 品级 / 状态 / 更多筛选     │
├─────────────────────────────────────────────────────────────────────┤
│ 图 │ 货号 / 品类 │ 销售 │ 花费 │ CTR │ CPC │ 直购成本 │ 加购 │ 品级│
│────┼─────────────┼──────┼──────┼─────┼─────┼──────────┼──────┼─────│
│    │             │      │      │     │     │          │      │     │
└─────────────────────────────────────────────────────────────────────┘
                                              点击行 → 右侧详情与评论
```

SKU 表格使用固定首列、可控列密度和一致数字对齐；不用大面积彩色标签代替数值。

### 6.3 品类梯队

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 品类梯队     [品类列表] [梯队地图]   品类 / 梯队 / 排序 / 顺序       │
├─────────────────────────────────────────────────────────────────────┤
│ 波段织带  7A ─ 7B ─ [7C]                                            │
├───────────────┬───────────────┬───────────────┬─────────────────────┤
│ core          │ potential     │ observe       │ tail                │
│ 数量 / 金额   │ 数量 / 金额   │ 数量 / 金额   │ 数量 / 金额         │
├─────────────────────────────────────────────────────────────────────┤
│ 品类列表：品类汇总 / 梯队分布 / 代表款 / 可展开完整 SKU 子列表       │
│ 梯队地图：品类 × 固定四梯队 / 零桶 / 代表款 / 单元上下文             │
└─────────────────────────────────────────────────────────────────────┘
```

- 默认使用“品类列表”，一级行连续呈现品类汇总、四梯队分布和最多三张代表款；`+N` 只表达未展示数量，展开后显示完整 SKU 证据。
- “梯队地图”固定使用 `core / potential / observe / tail` 四列，零数量单元仍保留；列头在深滚动时吸顶。未选中单元最多显示三张代表款，选中后单元与右侧上下文换行展示该梯队全部商品图。选择态同时联动品类标识、单元边框、背景和辅助技术状态，并显示带当前 SKU 数量的“查看明细”动作。下钻只打开当前单元明细，不改写全局品类/梯队筛选；列表顶部的返回地图入口在深滚动时保持可见，收起后仍保留完整品类列表。
- 商品图保持 4:5，并在列表、地图、SKU 子行和右侧上下文复用同一事实源；无图商品明确标记“待补图”。
- 1180px 以下地图按品类转为 2×2 单元；390px 列表转为品类卡和 SKU 子卡，关键触控目标不小于 44px。
- 梯队强调导入证据和真实变动，不使用游戏化排行榜、自动决策或无依据评分。

## 7. 图表规则

- 当前波段为橙色，对比波段为蓝色，其他历史为中性灰。
- 指标选择不得重定义橙蓝语义；“主分析 / 结果对照 / 驱动对照 / 结构分解”使用文字、边框和序列权重表达。
- 总览四图维持支付 → 效率 → 流量 → 品类的稳定 DOM 与阅读顺序；390px 只改为单列，不重排语义。
- “流量与成交”使用简写图例、三段量纲和受控刻度密度；在双列桌面布局中绘图区填满与品类浏览器同排的剩余高度，不把三段折线压在卡片顶部。
- 网格线只保留帮助读数的水平线，颜色不高于 `#E8E6E1`。
- 轴标题、单位、时间范围和数据截止时间必须可见。
- 金额默认使用完整人民币或“万元”单位；同一图中不得混用。
- 比较两条以上不同量纲指标时拆图，不使用双轴掩盖关系。
- 趋势使用折线或面积线；组成使用堆叠条；排名使用横向条；梯队变化使用阶梯轨迹或迁移表。
- Tooltip 采用白底、细边框、紧凑数字列；内容顺序与图例一致。
- 不使用 3D、仪表盘、彩虹配色和装饰性图形。

## 8. 表格与筛选

- 表格表头吸顶；首个标识列可固定。
- 数值右对齐，货号与文本左对齐，状态居中。
- 行 hover 只使用 2–3% 的墨色背景，不用高饱和铺色。
- 排序状态显示方向和优先级；空值显示“—”，不可计算显示“不可计算”。
- 全局筛选只保留波段、日期与必要业务维度；低频筛选进入“更多筛选”。
- 已生效筛选显示在紧凑条件条中，可逐项清除并显示结果数量。

## 9. 右侧上下文栏

- 右侧栏承载当前波段、品类、SKU 或分析卡片的详情、证据、评论和动作。
- 固定使用“摘要 / 证据 / 讨论”三标签；没有显式选择时显示当前页面默认业务对象。
- 指标、图表点、品类、SKU、导入梯队和分析记录都通过同一 typed `focus` 选择驱动，不再并存页面专用详情抽屉。
- 总览的 `metric` 表达可分享的指标透镜，typed `focus` 表达可分享的具体证据；有效深链同时恢复两者和右栏，无效 focus 不得污染合法筛选。
- 指标和日级点摘要使用与画布一致的编号分析路径，并同时显示“角色 + 目标图名”；路径定位保留查询参数，以焦点和目标描边确认当前证据位置。
- 打开右侧栏不改变主页面筛选和滚动位置。
- 评论采用白色与墨黑消息块；墨黑只用于当前用户或关键已确认结论。
- 分析证据标签提供“准备钉钉通知”入口；目标、正文和链接预览及显式确认保留在“分析与行动”主工作区。
- 窄桌面使用覆盖抽屉；`Esc` 关闭并把焦点返回触发元素。

## 10. 动效与状态

- 控件反馈 120–160ms；抽屉 180–220ms；图表数据切换 240ms。
- 页面不做逐卡片入场动画；只对波段切换使用一次协调过渡。
- 加载时保持真实布局骨架，避免页面跳动。
- 舒适/紧凑密度只改变页面间距、控件高度、表格行高和卡片内边距，不隐藏数据字段。
- 图表模块按需加载；减少动态偏好和 `prefers-reduced-motion` 同时关闭 CSS 与 ECharts 的非必要动画。
- 导入和发布显示阶段进度；成功后明确显示新数据版本。
- 支持 `prefers-reduced-motion`，关闭非必要过渡。

## 11. 自我校准

暖白与橙色容易落入常见 AI 仪表盘风格。为避免模板感，母版做了三项约束：

1. 不使用高对比衬线标题，改用克制无衬线与等宽数据字体，贴近实际经营工具。
2. 橙色只标记当前波段和行动重点，主视觉由栅格、商品证据和数字层级建立。
3. 使用与新品业务强绑定的“波段织带”作为唯一标志性元素，其他区域保持安静。

## 13. 第二轮设计工艺基线

- 可操作文字不低于 12px，必要紧凑信息不低于 10px；金额、日期、比例和 SKU 标识继续使用等宽数字与稳定列宽。
- 即时反馈使用 `120ms`，临时层与上下文切换使用 `220ms`；按压、焦点、选中、禁用和 busy 状态不得改变控件几何或先清空已发布内容。
- 菜单、Popover、命令面板、右栏与灯箱共享临时层标记、互斥关闭、`Esc` 焦点回退和同路径进出契约；右栏始终从右侧进入和退出。
- 加载、空态、错误与 stale 刷新保留真实内容尺寸；stale 状态继续显示旧内容并通过 live status 宣告更新。
- 1728×1117 使用完整三栏独立滚动；1440×1000 使用覆盖式右栏；1180px 及以下标题、元信息和页面操作分行；390×844 保持单列阅读顺序、44px 主要目标和页面级零横向溢出。
- 设置页“减少动态”与系统减少动态任一开启即关闭非必要动画；减少透明度取消功能悬浮层模糊并提高不透明度；增强对比度为选中态与浮层增加明确边框或轮廓。
- 唯一硬截图仍为 `frontend/e2e/__screenshots__/overview-1440.png`。其余页面和视口使用确定性布局断言与阶段视觉检查，不建立并行视觉母版。
